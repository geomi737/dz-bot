# Бот «скиньте дз» для WhatsApp и Дневник.ру

Работает с твоего аккаунта WhatsApp как связанное устройство. В указанной
группе отвечает на «скиньте дз», «кинь дз», «дай домашку», «пришлите домашнее
задание» и похожие команды. Команду можешь написать и ты сам со своего телефона.

- До **10:00** отправляет ДЗ **на сегодня**.
- С **10:00 включительно** отправляет ДЗ **на завтра**.
- Использует время исходного вопроса, даже если получение ответа затянулось.
- По умолчанию считает время по **Москве**, независимо от настроек сервера.
- Между ответами выдерживает **30 секунд**; запросы во время паузы пропускает.
- Отвечает только в заданной группе, личные чаты и другие группы пропускает.
- Всегда пишет день недели и полную дату, сохраняет ссылки из текста и HTML.
  Если API возвращает URL вложений отдельно, добавляет и их.

Берётся строго выбранный календарный день. Если на завтра нет ДЗ, бот пишет
об этом с датой; автоматически на понедельник или день после каникул не переходит.

Пример ответа:

```text
📚 ДЗ на четверг, 5 ноября 2026:

1. Химия — Повторить пройденный материал.
2. Английский язык — Exercise 7, page 61
3. Информатика — Выполнить задание (https://example.org/task)
```

## Настройка и запуск

Нужны Node.js 18+ и Python 3.9+ с базой часовых поясов IANA.
Сторонние Python-пакеты не используются.
Команды выполняются из корня проекта.

1. Установи зависимости: `npm install`.
2. Если `.env` ещё нет, скопируй `.env.example` в `.env` и заполни:

   ```dotenv
   DNEVNIK_TOKEN=твой_токен
   GROUP_NAME=точное название группы
   GROUP_ID=
   BOT_TIMEZONE=Europe/Moscow
   ```

   Достаточно `GROUP_NAME` или `GROUP_ID`. ID надёжнее названия, имеет вид
   `120363000000000000@g.us` или `79990000000-1234567890@g.us` и имеет приоритет.
   Если есть группы с одинаковыми названиями, обязательно используй `GROUP_ID`.
   Для другого часового пояса укажи, например, `Asia/Yekaterinburg`.
   ID ученика и школы бот определяет сам; при необходимости доступны
   `DNEVNIK_PERSON_ID` и `DNEVNIK_SCHOOL_ID`.
3. Выполни `npm start`.
4. При первом входе отсканируй QR своим WhatsApp:
   **Настройки → Связанные устройства → Привязка устройства**.
   Сессия сохранится локально в `.wwebjs_auth`.
5. Дождись «Бот на связи» и напиши «скиньте дз» в указанной группе.

Для работы процесс должен оставаться запущенным, а компьютер — включённым.
Остановка: `Ctrl+C`.

Если Python запускается другой командой, добавь в `.env` `PYTHON=python3`
или полный путь к интерпретатору.
Если Puppeteer не находит браузер, укажи путь к установленному Chrome:
`PUPPETEER_EXECUTABLE_PATH=/usr/bin/google-chrome-stable`.
Либо установи совместимый браузер: `npx puppeteer browsers install chrome`.

## Запуск в Docker

Нужны Docker Engine и Docker Compose v2 или новее. Готовый образ для Linux
x86_64 (`linux/amd64`) собирается в GitHub Actions и публикуется как
`ghcr.io/geomi737/dz-bot:latest`. Node.js, Python, Chromium и база часовых
поясов уже включены. Контейнер запускается от пользователя `node`, без прав root.
На сервере с 1 ГБ ОЗУ используй готовый образ: сборку на нём выполнять не нужно.

1. Если `.env` ещё нет, скопируй `.env.example` в `.env` и заполни
   `DNEVNIK_TOKEN` и `GROUP_NAME` или `GROUP_ID`, как описано выше.
2. Скачай готовый образ и запусти бота:

   ```bash
   docker compose pull bot
   docker compose up -d --no-build bot
   docker compose logs -f --no-log-prefix bot
   ```

3. Отсканируй QR из логов в WhatsApp и дождись «Бот на связи».
   `Ctrl+C` завершает просмотр логов; бот продолжает работать в фоне.

Файл `.env`, локальные зависимости и данные WhatsApp исключены из контекста
сборки. Compose передаёт настройки из `.env` при запуске. Пути `PYTHON` и
`PUPPETEER_EXECUTABLE_PATH` в контейнере заданы отдельно, поэтому локальные
пути к интерпретатору и браузеру менять не нужно.

Сессия WhatsApp и кеш хранятся в именованных volumes `whatsapp_auth` и
`whatsapp_cache` и сохраняются при пересоздании контейнера. При первом запуске
в Docker нужно привязать устройство заново: локальная `.wwebjs_auth`
автоматически не переносится. Не запускай две копии бота для одной группы
одновременно, иначе они могут отправлять повторные ответы.

```bash
# Остановить и удалить контейнер, сохранив сессию
docker compose down

# Обновить проект и образ без сборки на сервере
git pull --ff-only
docker compose pull bot
docker compose up -d --no-build bot

# Применить только изменения .env, не обновляя образ
docker compose up -d --no-build bot

# Проверить Python и формат сообщения внутри контейнера без обращения к API
docker compose run --rm --no-deps bot python3 -m src.dnevnik.fetcher --demo
```

`docker compose down -v` удаляет volumes, включая авторизацию WhatsApp.

### Публикация готового образа

Workflow `.github/workflows/docker.yaml` запускается при изменении Dockerfile,
зависимостей, исходников или тестов в `main`, а также вручную на вкладке Actions.
Перед публикацией он проверяет Node.js, Python и запуск Chromium в контейнере.
Образы получают тег `latest` и тег `sha-<полный SHA коммита>` для выбора
конкретной версии через `BOT_IMAGE` в `.env`.

После первой публикации владелец GitHub-аккаунта должен один раз открыть
[настройки пакета](https://github.com/users/geomi737/packages/container/dz-bot/settings)
и выбрать **Change visibility → Public**. До этого GHCR может возвращать
`denied` при скачивании без авторизации. Публичность репозитория сама по себе
не делает образ публичным. Новые версии сохраняют настройку видимости пакета.

### Локальная сборка

Для разработки на компьютере с достаточным объёмом памяти:

```bash
BOT_IMAGE=dz-bot:local docker compose up -d --build --pull never bot
```

Для отдельной сборки без запуска: `docker build -t dz-bot:local .`.
На слабом сервере не используй `--build`: скачивание готового образа исключает
нагрузку от установки Chromium и npm-зависимостей во время сборки. Расход памяти
самого работающего бота при этом не меняется.

## Доступ к Дневник.ру

Используется `DNEVNIK_TOKEN`, передаваемый API в заголовке `Access-Token`.
Логин, пароль и куки браузера не нужны и не используются.
В `.env.example` сохранена ссылка для получения OAuth-токена из авторизованной
сессии Дневник.ру. Перед выдачей доступа проверь название приложения и права.
Файл `.env` и каталог сессии WhatsApp исключены из Git.

Запросы к API выполняются по HTTPS с проверкой сертификата, без перенаправлений
и прокси из окружения. Сетевые ошибки обрабатываются без вывода токена.

## Проверка

```bash
# Пример сообщения без сети и отправки в WhatsApp
python3 -m src.dnevnik.fetcher --demo

# Реальное ДЗ с токеном из .env, только вывод в терминал
python3 -m src.dnevnik.fetcher

# Тесты без настоящего токена, сети и отправки сообщений
npm test
python3 -m unittest discover -s tests -v
```

Для проверки даты по конкретному времени вопроса есть `--at UNIX_SECONDS`.
`--debug` выводит полученные данные дневника в stderr для отладки;
этот вывод может содержать личные данные.

## Файлы проекта

- `src/whatsapp/bot.js` — подключение к WhatsApp через whatsapp-web.js.
- `src/whatsapp/message-handler.js` — команды, фильтр группы и пауза между ответами.
- `src/dnevnik/fetcher.py` — выбор даты, получение ДЗ и форматирование ссылок.
- `src/dnevnik/client.py` — клиент API Дневник.ру на стандартной библиотеке Python.
- `tests/` — проверки обработки сообщений, дат, ссылок и API.
